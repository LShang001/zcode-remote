# 2026-09-14 v2.12/v2.13 置顶与多窗口预研

## v2.12 电脑列表置顶

- `HistoryItem` 加 `pinned` 字段(JSON 里只写 true,不写 false 保持老格式干净);
  `getHistoryList()` 统一排序:置顶优先,其余按 time 倒序——**列表与桌面动态快捷方式共用这一处顺序**,
  所以置顶自动同步到快捷方式,不需要额外代码。
- 长按菜单按状态切换文案("置顶(排在列表最前)"/"取消置顶");`recordHistory` 保留 pinned
  (和保留 name 同理,不能因为"用了一次"就把置顶丢了)。
- 列表项标题前缀 `📌 `;当前电脑仍是"● + 高亮框"。
- 验证:三台电脑预置 → 置顶 CCC(最旧)排到首位且带 📌 → prefs 落 `pinned:true` →
  `dumpsys shortcut` 确认 session_0 = CCC → 取消置顶后恢复按时间排序。全程无崩溃。

## v2.13 折叠屏适配(多窗口的第一步)

- Manifest 两个 Activity 的 configChanges 补 `smallestScreenSize|screenLayout|density|uiMode`:
  折叠展开/分屏调整这些变化不重建 Activity,WebView 不再整页重载。
- `onConfigurationChanged` 兜底:MainActivity 把 FAB 拉回安全边距(`clampFabInBounds`),
  ScanActivity 重算预览留边(`fitSurfaceToPreview`)。
- 验证:模拟器旋转横竖屏,会话保持、FAB 坐标正确重算、无崩溃。

## 多窗口可行性(结论已落 docs/multi-session-feasibility.md)

- 两条主路线:**A 同 App 多 task**(开发量中,依赖 OEM 分屏是否允许同一 App 选两次)、
  **B App 内多窗格**(开发量大,但唯一能保证折叠屏左右并排且不受 OEM 限制)。
- 关键平台事实:多 WebView 默认共享 Cookie/DOM storage(必须用 androidx.webkit Multi-Profile 隔离);
  documentLaunchMode 要求 launchMode=standard(与现有 singleTask 冲突);
  onRenderProcessGone 会对每个受影响 WebView 各回调一次。
- 6 个必须先验证的不确定点写进文档(含"网页端能否同机双会话"这个前提)。
