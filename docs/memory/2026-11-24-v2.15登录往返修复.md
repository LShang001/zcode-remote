# 2026-11-24 v2.15:桌面端 4.0.0 后手机"连不上"的根因与修复

## 现象

用户给出远程链接(`/remote/v4?sid=d_Un2oo...&mid=...&name=LS-MechRevo-16U&app_version=4.0.0`)反馈 App 连不上。
桌面端日志显示手机端**其实配对成功过多次**(`paired` / `pair-status matched` / `workspace bridge active`,
初始化 RPC 全部 OK),但每次 15–110 秒后掉线重连——表象容易被误判成"中继掉线"。

## 排查结论

1. 服务端与链接都没问题:页面 200、61 个 JS/CSS 资源全部 200;会话 sid 自 11-12 起未变。
2. 变化点:桌面端 11-23 15:03 自动升级 **3.18.1 → 4.0.0**,远程网页 11-22 起也是 4.0.0 构建。
3. 新网页(4.0.0)**强制登录与电脑端相同的账号**:未登录时显示 "ZCode — Sign In To Continue",
   登录是整页 OAuth 往返(`zchat.z.ai` / `chat.z.ai` / `bigmodel.cn` → 回调 `zcode.z.ai/remote/v4?...`
   换取令牌 → `location.replace` 回远程页),等待页自己不轮询。
4. 壳(v2.14 及以前)把 `zcode.z.ai` 以外的主框架导航都甩给系统浏览器 → 授权页在 Chrome 打开,
   回调页与待处理登录记录都不在 WebView 里,壳内永远停在 "Waiting for authorization"。
   logcat 实锤:`START u0 {act=android.intent.action.VIEW dat=https://zchat.z.ai/...} from uid 10193`
   (10193 = com.zcode.remote),随后 Chrome 抢焦点。

## 修复(v2.15,MainActivity)

- `SIGNIN_HOSTS = {zchat.z.ai, chat.z.ai, bigmodel.cn}`(含子域)与会话域名一起在 `shouldOverrideUrlLoading` 放行。
- 子框架(`!request.isForMainFrame()`)不再 `openExternal`,交 WebView 正常加载。
- `showWeb` 增加 `onSigninPage()` 分支:停在登录域名时也 `loadUrl`,否则「返回会话」只掀覆盖层不导航。
- 返回键 `backStepSkippingSignin()`:跨过授权页历史条目(退回去只会看到失效的授权页)。
