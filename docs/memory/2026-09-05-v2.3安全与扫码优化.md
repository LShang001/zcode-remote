# 2026-09-05 v2.3:安全加固 + 扫码优化 + 体验修正

> 本轮从"分析如何改进"到完整实施 v2.3。versionCode 14 / versionName 2.3,模拟器 x200(X200 Ultra 近似屏)视觉审查通过,相册选图解码 E2E 打通。

## 改了什么

**安全(高优先级)**
- **镜像下载 APK 强制验签**:第三方加速代理是不可信通道(HTTPS 只到代理,返回内容由代理决定)。下载完成后 `getPackageArchiveInfo(path, GET_SIGNING_CERTIFICATES)` 校验 ①包名==com.zcode.remote ②versionCode>已装 ③签名集合与已装本应用逐字节一致,全过才拉起安装器。**文件不是有效 APK(代理返回错误页/垃圾)→ 换下一个源;签名/包名不符(投毒)→ 直接阻断弹窗,因为所有镜像服务的是同一个 GitHub 文件,换源无意义。**
- **allowBackup=false** + 新增 `res/xml/data_extraction_rules.xml`(禁云备份+设备迁移):SharedPreferences 里的远程链接带 sid,等于控制电脑的凭证,不能随 Google 备份/adb backup 外泄。
- **剪贴板监听改造**:从"每次 onResume 轮询读内容"改为 `addPrimaryClipChangedListener` + 回前台按 `ClipDescription.getTimestamp()` 去重,内容没变不读,减少 Android 12+ 每次切回都弹"已粘贴自…"系统提示。listener 在 onDestroy 注销(系统级单例,不注销会泄漏 Activity)。

**扫码(ScanActivity)**
- **删掉每帧 w*h 次像素旋转**:QR 码有三个定位符,zxing 原生支持任意朝向。JVM 实测 0/90/180/270° 直接喂 NV21 的 Y 平面(原宽高)全部解码成功。每帧省掉双重循环 + 一次整块分配。
- **误识别 Toast 刷屏修复**:对着非 ZCode 二维码时原来每帧(180ms 节流)弹一次 Toast;加状态位,只在"识别到二维码但非远程链接"状态首次切换时弹一次,取景框边框同步变红;成功变绿 + 30ms 震动。
- **识别率**:预览帧只取画面中心 70% 区域送解;HybridBinarizer 失败后用 GlobalHistogramBinarizer 兜底(暗光/低对比度),相机预览与相册选图两条路径都加。
- 新增 VIBRATE 权限(普通权限,安装即授予)。

**体验/健壮性**
- **版本号单源**:删掉 MainActivity 里的 `APP_VERSION` 常量,运行时读 `PackageManager.getPackageInfo(...).versionName`,菜单/关于/设置页/更新比较全走它,发版不再两处人肉同步(gradle 成为唯一来源)。
- **安装授权续装**:原来引导去"安装未知应用"授权后要重新检查更新+重新下载;现在暂存 downloadId,`onResume` 发现权限已给且有待装包就直接续装。
- **下载卡住判定**:PAUSED(系统等网络/切 Wi-Fi)不再计入 20s 无增长超时(暂停期间持续刷新计时戳),避免弱网无谓轮换所有源;只有 RUNNING 才判 stall。
- **destroyWeb 先从父容器 removeView 再 destroy()**:destroy() 只清原生资源,仍挂视图树的 WebView 之后收布局事件会打已销毁内核,偶发崩溃。顺带把 progress/fab 置 null。
- **设置页非远程链接二次确认**:粘贴的不是 `https://zcode.z.ai/remote...` 时弹"这似乎不是 ZCode 远程链接,仍要打开吗?",不阻拦但防手滑。
- **外链 intent:// 处理**:`Intent.parseUri(URI_INTENT_SCHEME)` 解析,目标 App 不存在时按 browser_fallback_url / market 兜底。
- **WebChromeClient.onPermissionRequest**:网页请求麦克风/摄像头时,有对应系统权限(RECORD_AUDIO/CAMERA)才授予,否则 deny(不主动申请权限,保持壳的本分)。
- **主题色统一**:styles.xml 加 `colorAccent` + `colorControlActivated` = #4C8DFF,对话框按钮文字和 Switch 选中态从系统默认青绿改成 App 蓝。

- JVM(zxing core 3.5.3 jar)独立测试:生成 QR → 旋转 0/90/180/270° → PlanarYUVLuminanceSource 直解,四种朝向全 PASS。
- 模拟器 x200:设置页 footer v2.3 ✓;非远程链接弹二次确认 ✓;扫码页相机预览+蓝色取景框+权限弹窗 ✓;**相册选图 E2E**:生成含 `sid=e2etest987654321` 的 QR 图 → push + scan_file 入库 + 清 is_pending → 系统选择器选图 → 解码成功回传 → MainActivity 加载会话 ✓;菜单标题 v2.3、开关变蓝 ✓。

## 追加:真实二维码截图暴露相册解码短板(同日实测补强)

用户发来桌面端真实"手机扫码连接"截图后 JVM 诊断发现:真实远程链接 **208 字符**(sid+hash+mid+name+app_version),QR 是高版本密集码;相册选的是"二维码只占画面下方一小块的整窗截图"时,**原图直解(两种 Binarizer)失败、放大 1.5x 也失败,只有整图最近邻放大 2x + Otsu 大津法二值化成功**(zxing 自生成同等密度码能解回自己,证明库没问题,是截图模块像素偏小)。
- 修法:`ScanActivity.decodeGalleryImage` 原图失败后追加 `decodeQrFromBitmap(bmp, true)`——最近邻放大(系数 min(2.0, 2600/最长边),不插值保硬边缘)+ Otsu 自动阈值 + 二值化再解,两种 Binarizer 照旧兜底。相机预览是连续帧、模块够大且要实时,不加这套。
- **真实链路验证通过**:模拟器相册选这张真实截图 → 解出链接 → WebView 显示"已连接到当前桌面窗口"(用户真机 LS-MechRevo-16U 会话)。
- 内存峰值约 47MB(2x 二值 int[]),现代手机无压力。

## 新增踩坑(已同步 AGENTS.md)

- zxing 解码 QR 无需旋转预览帧(三定位符支持任意朝向),旋转是纯浪费。
- 相册密集 QR:原图/1.5x 直解失败,2x 最近邻放大 + Otsu 二值化才成功。
- exported=false 的 Activity 用 `adb am start` 拉不起(SecurityException),视觉审查要从 App 内按钮进入。
- 系统控件着色:对话框按钮文字取 colorAccent,Switch 选中态取 colorControlActivated,统一主题色两个都要设。
