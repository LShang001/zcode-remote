# 2026-09-06 v2.4:会话秒回(覆盖层架构) + 扫码绑定快捷方式

> versionCode 15 / versionName 2.4。x200 模拟器用**真实桌面会话**验证通过:秒回像素级保留滚动位置、遮挡期间页面仍实时更新。

## 会话秒回:页面切换从"销毁重建"改为"覆盖层"

**之前**:`showSetup`/`showError` 开头 `destroyWeb()` 把 WebView 整个销毁,`root.removeAllViews()` 后放设置页;点"返回会话"= `showWeb()` 新建 WebView 重新 `loadUrl`,几秒白屏、滚动位置丢失、SPA 状态重置。

**现在**(MainActivity 约 2050 行):
- 新增字段 `sessionView`(RefreshLayout,内含 WebView+进度条+悬浮钮)与 `overlayView`。`buildSessionView()` 整个 App 生命周期只建一次,固定挂在 `root` 的 **index 0**(最底层)。
- `showSetup`/`showError` 不再销毁任何东西,把自己的视图交给 `showOverlay(v)` 叠在会话层之上;`removeOverlay()` 掀掉即回到会话。
- `showWeb(url)` 三分支:① `sessionView==null` → 首次构建;② url 与 `loadedUrl` 不同 → 同一 WebView 实例直接 `loadUrl`(历史/扫码/剪贴板切会话都是秒切);③ url 相同 → **什么都不做**只 `removeOverlay()`,这就是秒回。
- `webLoadFailed` 标志:`showError` 置 true;url 相同分支若为 true 则 `reload()` 而非只掀覆盖层——否则"错误页→设置页→返回会话"会露出 WebView 内核的错误白页。`loadUrl/reload` 路径清零。
- `onBackPressed`:有覆盖层且非错误页 → `removeOverlay()`(设置页按返回=回会话);错误页覆盖层仍走"再按一次退出"。原 `canGoBack→goBack` 保留但排除错误态。
- 网络恢复重连(`onAvailable`):`webView!=null` 时显式 `removeOverlay()+reload()`,不能走 `showWeb`(url 相同分支不会 reload)。
- `route()` 的 onNewIntent 同链接场景:若有覆盖层则 `removeOverlay()`,不重载。
- `destroyWeb()` 仅 `onDestroy` 调用,顺带清 `sessionView`。

**验证(真实会话,x200)**:会话页滚到中部 → ⋮ → 更换链接(设置页覆盖层,footer v2.4)→ 返回会话,**0.4s 内截图与进入前像素级一致**,无进度条。加分细节:遮挡期间某任务由"运行中"变"已完成",说明会话层被盖住时 WebView 仍在实时接收数据(会话保活,回来看到的是最新状态)。设置页按返回 → 回会话不退出 ✓;下拉刷新回归 ✓;断网 → 壳错误覆盖层 ✓ → 错误页按返回不掀层 ✓ → 恢复网络自动重连掀层 reload ✓。

## 扫码绑定快捷方式

`shortcuts.xml` 新增 `scan_bind`(action `com.zcode.remote.SCAN_BIND`,strings `sc_scan`/`sc_scan_long`)。`route()` 解析该 action 后**先走正常加载逻辑(会话页/设置页)再 `startScan()`**,这样取消扫码回来不留白屏;`startScan()` 与设置页按钮共用。验证:`am start -a com.zcode.remote.SCAN_BIND` → ScanActivity 前台 → 返回取消 → 回到会话页且滚动位置仍保留 ✓。

## 踩坑与发现(耐久部分已同步 AGENTS.md)

1. **开发中抓到的 bug**:`buildSessionView` 尾部和 `showWeb` 各 `root.addView(sessionView)` 一次 → 启动即 `IllegalStateException: child already has a parent` 崩溃。模拟器"眼见为实"第一轮就抓住了,改为只在 `buildSessionView` 内 `addView(…, 0, lp)`。
2. **菜单坐标会随"当前会话"URL 长度漂移**:真实链接 208 字符在菜单头部占 4 行,把所有菜单项往下推约 120px,按旧截图坐标点会点错项(点到"刷新会话")。模拟器自动化点菜单/对话框项**一律用 `uiautomator dump` 查 bounds 取中心**,不要硬编码坐标。
3. **宿主机开代理(fake-ip)时模拟器造不出传输层失败**:`nonexistent.invalid` 竟解析到 198.18.0.32 且 ping 通(Clash 类 fake-ip 段),WebView 卡在 TLS 握手等超时,错误页迟迟不出;`zcode.z.ai:81` 也被代理接管。**测壳错误页/自动重连用断网法**:`svc wifi disable; svc data disable` → 秒出错误覆盖层;`svc … enable` 触发自动重连。emulator-review.md 里"预置死链看错误页"的方法在此环境下失效。
4. `sid=deadbeef404` 这种无效 sid 返回的是 HTTP 200 + 官方网页自己的"Mobile Connection Invalid"错误 UI,壳不干预(也不该干预)——壳错误页只管 DNS/连接/超时/HTTP 4xx 这类传输层失败。
5. 既有边缘行为(非本次引入,未改):`net::ERR_CONNECTION_CLOSED` 映射的错误码不在 v1.9 白名单(HOST_LOOKUP/CONNECT/TIMEOUT)里,主框架落到 WebView 内核白页而非壳错误页。若真机遇到可考虑主框架任何 `onReceivedError` 都走壳错误页。
6. uiautomator dump 抓不到 Toast(独立窗口不在 view 树),验证"再按一次退出"这类提示要看副作用(覆盖层是否仍在/App 是否存活)而非找文字。
