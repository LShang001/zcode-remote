# 2026-09-14 v2.9 多维度审计修复

本轮用"只读扇出审计(4 个正交子代理)+ 单线程写入修复"模式全量审计了三个 Java 源文件与构建/资源,
共核实并修复 20+ 处问题,重点如下(耐久规则已同步进 AGENTS.md §踩坑记录,此处只记轮次要点):

## 修了什么

1. **自愈后触摸全失效(P0)**:destroyWeb 只摘 WebView 不摘 sessionView 容器,自愈重建后旧容器留在 root
   顶层吃掉全部触摸。模拟器 kill -9 sandboxed_process0 实测:修后自愈完成菜单可正常点开。
2. **返回键路径三态收敛**:错误页→设置页→返回键不再露内核白页(且保住网络恢复自动重连);首启无会话
   按返回直接退出不黑屏。断网/恢复/返回路径全部模拟器实测。
3. **应用锁 Android 9 崩溃(P0)**:BiometricManager 是 API 29+,原 `< 28` 门槛让 Android 9 必崩
   (NoClassDefFoundError,catch 兜不住);28 改用 FingerprintManager 预检。
4. **安全三件套**:data_extraction_rules 逐域排除(root 不覆盖 shared_prefs,官方文档实证)、
   intent:// 前 setComponent(null)、WebView 摄像头请求改为用户确认(删死代码音频分支)。
5. **debug 包不再当正式包发**:新增 release 变体(debuggable=false + debug keystore 签名),
   覆盖安装验证通过(run-as 报 not debuggable 自证生效)。
6. **更新链路硬化**:检查防重入/销毁守卫/节流时间戳移到成功后;stall 判据 `!=`(回退也是"在动");
   系统侧取消不换源;失败路径统一 dm.remove + 缓存副本回收;pending 状态持久化 + 启动对账。
7. **扫码页重构**:解码全链路下沉 HandlerThread(Camera1 buffer 复用必须先拷 ROI)、onResume 重开
   相机、权限拒绝/相机失败保留相册出路、预览按比例留边、OOM 兜底、按钮 48dp。
   相册选 QR 端到端实测通过(推图入库+选择器选中→自动识别回会话)。

## 方法要点

- 4 个子代理按文件所有权切分(MainActivity / Updater / ScanActivity / 清单资源),只读、互不重叠;
  主代理逐条核实(34 条报告核实后修 20+,驳回/降级若干),写入全部单线程。
- 子代理报告质量参差:高价值的是"逻辑链逐行可追"的结构性缺陷,低价值的是过度推测;
  凡改动都先本地读代码确认,不直接照搬。

## 追加:v2.10 更新说明进弹窗(同日,用户要求"每次升级要有更新说明")

- 用户诉求:发版不能只有版本号,要让用户在 App 里看到这次改了什么。
- 实现:Updater 检查更新从"正则抓 tag/asset"改为 **JSON 解析 Release 响应**(`tag_name`/`body`/`assets[]`),
  `body`(Release notes)经轻度 markdown 清理(`#`/`**`/反引号,超 3000 字截断)后拼进"发现新版本"弹窗;
  正则仅作 JSON 结构突变的兜底。
- 验证:伪装版本号法(临时 2.8.9)让真 v2.9 Release 触发更新弹窗,实测弹窗完整展示 notes;
  恢复 2.10 正式版后"检查更新"正确报已是最新。
- 规约升级(已进 AGENTS.md §原则 3/4):发版四项同步 = versionCode + versionName + Release(tag + APK + **必写 notes**);
  notes 必须面向用户写(不写 commit/文件名/内部代号),因为它就是用户看到的更新说明。
